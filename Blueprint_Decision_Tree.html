When to Create a New Record

Decision framework for Blueprint · Variation · Item · BOM

New project or change request
Step 1 — Blueprint
Is this a new customer, or a new product for an existing customer?
Yes
Create new Blueprint
Then create a new Variation
No — existing Blueprint
Evaluate what changed below ↓
Same Blueprint — evaluate changes
Step 2 — Variation
Did anything change that affects project price?
WIP size changed · Pallet qty changed · Labels added or removed
Yes
Create new Variation / PC
Get Ops + Engineering approval before creating Item
No — same Variation
Evaluate finished good below ↓
Same Variation — evaluate finished good
Step 3 — Item
Did the physical pallet change AND does the customer designate it as a new item in their system?
Both conditions must be true · See service modification note below
Yes — both true
Create new Item
Then create a new BOM + BOM Revision
No — one or both false
Keep existing Item
Treat as a service modification
Evaluate component recipe
Step 4 — BOM
Did the component recipe change?
New materials used · A sticker added but item stayed the same · Any component add / remove / qty change
Yes
Create new BOM + BOM Revision
BOM = parent · BOM Revision = component items
No
Keep existing BOM
No changes needed
BOM structure: Every BOM always has a BOM Revision attached to it. The BOM is the parent record. The BOM Revision holds the individual component items (packaging materials, raw materials, stickers, etc.).
Quick reference
Blueprint
New customer or new product line
Variation / PC
WIP size change · Pallet qty change · Labels added · Anything affecting project price
Item
Physical pallet change AND customer designates as new item in their system — both required
BOM + Revision
New materials · Sticker added · Any component recipe change
Service modification: A physical change the customer does not designate as a new item in their system. Use the existing Item. Ship & Receive fulfills against the existing item number.
